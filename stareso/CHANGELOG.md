- 2026-10-21: new build profile `day <limit>` (default 2h): eco's loop with full autonomy while the user works on the same computer. It asks no question and skips and lists the slices that need the user. Every `check` and `shot` runs with `DAY_MODE=1`, so the idle gate opens a window only when the user has been away for a few minutes, and deferred windowed tests run once at the end of the milestone. The run stops at the wrap-up time (deadline minus 10 min) or at 80 % of the 5-hour or weekly usage window, and ends with `MILESTONE DONE: M<n> · next: M<n+1>` or `RUN STOPPED: <reason>` so that a manager session can relay the next milestone. The Claude Code argument hint lists `day <limit>`. DESIGN-NOTES records the manager-session proposal (not applied, to raise at the next retro). Reason: a build in `night` or `fast` mode stole the typing focus and cannot run while the user works.
- 2026-10-21: manager launch (DESIGN-NOTES "Proposed 2026-10-21", applied at the user's request before a retro). The session that runs `status` can act as the project's manager: status §5 ends with one question, launch the next step in a new session, and on the user's yes it starts build, test or improve in the project folder without a worktree, with the step's tier and permission mode. Before a build it refreshes `docs/USAGE.md`, it never launches while another session works in the same checkout, it reuses an idle child, and it relays to the next step only when the user accepted the relay. Build, test and improve accept a manager's launch message as if typed and end with `MILESTONE DONE`, `STEP DONE` or `RUN STOPPED`. In Claude Code, build loses `disable-model-invocation` (a child could not start it from a message) and its description and "Started by" line keep it user-started. The Claude Code block gives the `start_session` and `clear_session` calls and the model and mode limits, and the capability row is proposed until one build is measured (conductor context per turn, "Carried" against project A M5). Reason: the user keeps one manager session per project and wants each step in its own launched session.
