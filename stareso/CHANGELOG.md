- 2026-10-20: new hook `tools/workflow-changed.mjs` (installed in the user settings: SessionStart, UserPromptSubmit, PostToolUse on Agent): a running session learns that the workflow changed since it last looked (commits, changed skills, shared files, helper definitions) and re-reads the skill it is running, so no conversation has to be told by hand. Helper definitions may still need a new session. Silent when nothing changed.
- 2026-10-20 (cross-project review): new `stareso/metrics.md` defines every retro metric once (definition, source "records" or "usage", tool, target, reference), and the retro skill points to it. "Profile used" and "Records drift" become one "Anomalies" line, because both were flat everywhere. `session-stats --log` adds "Planning cost per planned slice" (≈ equiv of an improve or test step ÷ the slices its commits added to the roadmap, target < 300k), because improve cost 3.5M per run on Opus and nothing measured it. It also counts conductor-built slices from BUILD-LOG (target 0), measures Carried above the base context every new session pays (median first-turn context, about 70k), so the < 20 % target can be met, and gains `--dry-run`.
- 2026-10-20 (portability, stage 1): the steps and helper roles move into a harness-neutral core (`stareso/skills/<name>/SKILL.md` in the Agent Skills format with `name` and `description` only, `stareso/roles/`), written in tiers (strong, standard, light), `AGENTS.md`, `<stareso>` paths and capability wording. Every harness-dependent feature is a capability with a concept file in `capabilities/` (helpers, read guard, automation, model tiers, browser, questions, step invocation, usage reader) and a row per harness in `harness/<harness>/capabilities.md` (level native, partial, manual or none, status proposed, measured, adopted or rejected, evidence). Claude Code rows are adopted with their measured evidence, while Codex, Cursor, Gemini CLI and chat-only rows are proposed from the docs, with models "to measure". `tools/harness-build.mjs` generates the Claude Code skills and agents from the core and `harness/claude-code/` (models.md, wording, blocks, frontmatter, agent heads), so no step reads a porting file at run time. Nine generated files came out identical, and the others grew by 0.9 % (build: the `tier:` alias), 5.0 % (init: the canary), 4.0 % (retrofit: the canary) and 3.0 % (retro: the harness's capabilities file). Init and retrofit now run a read-guard canary (`private/backups/CANARY`, expect a refusal, `Guard:` line in PLAN), because the guard was never checked. A deny rule written mid-session refused the Read tool at once. `slice-done` writes harness, helper mode and tier in every BUILD-LOG line (`--harness`, `--helper`, `--tier`, defaults from the project instructions, else claude-code, subagent and the brief's tier), and `roadmap-overview` reads `tier:` briefs. `metrics.md` gains "Evaluating a capability on a platform" and a no-regression check against SecuSurf M5 and Scriba M28 for the next Claude Code build. The retro reads the harness's capabilities file. `workflow-changed` maps core sources to steps and agents and reports stale generated files. `PORTABILITY.md` is folded into `harness/`, and `START-HERE.md` is new. Reason: colleagues on other assistants and people new to AI should run the same workflow, without any extra cost in Claude Code.
